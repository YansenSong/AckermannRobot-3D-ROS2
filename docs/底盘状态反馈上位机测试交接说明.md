# 底盘状态反馈上位机测试交接说明
适用版本 CAN1 SJW2 对照版 · 2026年9月17日

## 当前验证结果与测试目的
运控板已成功接收 EPS 的 0x18F 真实角度报文。现场 Keil 截图显示 CAN1 ESR=0、接收错误计数=0；左侧拉满时角度字段为 274000，即 +27.4°。速度和刹车反馈此前已由上位机测试正常。本次请重点验证新版 UDP 收包、转角显示及运行稳定性；最新角度在上位机的完整链路尚待确认。

## 本次更改
1. CAN1 保持 250kbps 和 87.5% 采样点，重同步宽度 SJW 从 1TQ 改为 2TQ，BTR 从 0x001C0003 改为 0x011C0003。现场接收已改善；不据此认定长期时钟精度已完成验证。
2. 根据实车确认的“CAN 原始值 300 对应现实 30°”，反馈角度按原始计数÷10换算；保留 SteeringRaw 原始计数。原转向控制指令、CAN2、USART 和 CH5 遥控接管逻辑不变。

## 网络与状态包
STM32:192.168.5.50/24；工控机:192.168.5.11/24。原 cmd__ 26字节控制端口仍为 5000。状态 UDP 源/目标端口均为 5001，目标 192.168.5.11，20ms 发送一次，约50Hz。状态帧固定56字节、Version=1；多字节 Big‑Endian，带符号整数为补码。

| 偏移 字节 | 字段与格式 |
| --- | --- |
| 0‑5 | sta\_\_ 五字节 ASCII + Version u8=1 |
| 6‑9 | ValidFlags u8;ControlSource u8;EnableState u8;Counter u8 |
| 10‑13 | TimestampMs u32，STM32周期汇总时间 |
| 14‑21 | DriveEncoderCount i64，当前0且无效 |
| 22‑25 | ActualSpeed i32，m/s×10000 |
| 26‑29 | ActualSteeringAngle i32，°×10000 |
| 30‑33 | SteeringRaw i32，EPS原始signed16计数符号扩展 |
| 34‑37 | BrakeMode u8;BrakeActual i16在35‑36;Gear i8在37 |
| 38‑43 | RT49Status / EPSStatus / SEBStatus，各u16 |
| 44‑48 | FaultFlags u32在44‑47;LastCmdCounter u8在48 |
| 49‑55 | 49‑51保留0;52‑55 Checksum u32 = sum(byte0..51) & 0xFFFFFFFF |

## 上位机字段换算与有效位
| 字段 | 显示换算 | 有效位 |
| --- | --- | --- |
| ActualSpeed | 字段÷10000 → m/s；来源为实测RT49 RPM÷3000 | ValidFlags bit1 |
| ActualSteeringAngle | 字段÷10000 → °；原始300→字段300000→30° | bit2 |
| SteeringRaw | 保留原始计数；如需角度，原始值÷10 → ° | bit3 |
| BrakeActual | BrakeMode=1:÷100 → MPa；=2:÷10 → mm；=0未知 | bit4 |

> 注意：ActualSteeringAngle 已在 STM32 内完成÷10换算，上位机仅除以10000，不要再次除以10。
> 有效位清除时显示“无效”，不能将填充值0当作实际零值；编码器当前没有真实来源，bit0保持0。

ValidFlags：bit0编码器、bit1速度、bit2换算角度、bit3原始角度、bit4刹车；bit5 RT49、bit6 EPS、bit7 SEB状态新鲜。EPS角度两项正常时 mask 0x0C 应为0x0C。设备状态/测量200ms无更新后清对应有效位。

FaultFlags 位19说明旧版速度系数口径，位20说明转角完整机械标定尚未完成；这些不是 CAN 数据失效标志。脚本用 steering_angle_deg 查看本次实测比例角度；road_wheel_deg 因位20保留可能显示 INVALID。不要把 FaultFlags 非0统一显示为严重故障，也不要把未知使能当作已确认失能。

## 最小测试步骤
1. 工控机连接对应网卡并配置 192.168.5.11/24，启动接收程序监听 UDP 5001；确认收到的来源为 192.168.5.50:5001，包长56、帧头sta__、Version=1，累加校验正确。无需为测试状态反馈额外发送运动命令。

2. 使用交接包内匹配版本的 udp_status_test.py，仅接收并保存30秒数据。检查 Counter 按 0‑255回绕、TimestampMs随时间增加、平均接收频率接近50Hz；Counter表示发送尝试，允许出现丢包跳号。
```
python udp_status_test.py --duration 30 --log sta56_test.jsonl
```

3. 按现场安全流程分别记录回中、左转、右转。同步比对 Keil 的 g_vehicle_status.actual_steering_x10000 和上位机字段：本次左侧拉满参考 +27.4°，其余方向和零位需实测。观察角度有效位及EPS状态有效位，同时复查速度、刹车反馈。

4. 持续运行5‑10分钟，确认角度报文计数增长、接收错误不持续增加、上位机收包稳定。条件允许时做受控反馈中断测试：检查200ms后对应CAN有效位清除；UDP整体断流需由上位机独立判断通信超时。
