- 适用固件：`Application_IP5_STA56_CAN1_SJW2_Trial`（2026-09-17 交接版）及后续版本
- 上位机侧：`real-vehicle-integration` 分支
- 日期：2026-09-18

本文档只列**缺口**与**需下位机确认/提供**的内容。56 字节布局、字段偏移、有效位与枚举的权威定义见
`docs/上位机接口说明_STA56.md`，此处不重复。

---

## 0. 背景与结论

上位机侧要基于 `sta__` 回传实现轮式里程计，用途有两个：

1. LIDAR/IMU 定位短时失效时的兜底；
2. 作为定位算法的高协方差运动先验。

回传通路已经通了——按 2026-09-17 交接与上位机侧最新测试，速度与转角字段均随实测变化（左侧拉满角度字段
274000，即 +27.4°）。

**但通路通不等于数值可换算。** 里程计需要的是**换算常数的物理含义**，而目前最关键的两个常数在固件侧就
标注为未标定（`FaultFlags` 位 19 / 位 20）。按现状直接实现出来的里程计不是"没数据"，而是**带着一个未知
比例系数**：数值平滑、曲线正常，但行驶距离和航向变化与实际成固定倍数关系。这类错误比完全没数据更难
发现——没有哪一帧看起来是错的。

因此在本文档第 1～3 项确认前，上位机不会把底盘回传接入定位链路，也不会让它发布 TF。

### 缺口一览

| # | 缺口 | 阻塞程度 | 主要责任方 | 验收方式 |
|---|---|---|---|---|
| 1 | 转角口径：EPS 轴角 → 等效前轮角、转角零位 | **阻塞** | 下位机 + 机械 | 定半径圆试验（6.2） |
| 2 | 线速度系数、RT49 反馈路数 | **阻塞** | 下位机 | 10 m 直线试验（6.1） |
| 3 | 速度与转角的符号约定 | **阻塞** | 双方确认 | 前进/倒车 + 左右打满 |
| 4 | 采样时刻定义、重启与回绕的区分 | 影响精度 | 下位机 | 书面确认 |
| 5 | 真实累计编码器来源（位 0） | 非阻塞 | 下位机 | 可选 |

## 1. 转角口径（FaultFlags 位 20）—— 阻塞项

### 现状

`ActualSteeringAngle` 取自 EPS `0x18F` 角度字段，固件内已完成 ÷10 换算，按 `WHEEL_PER_EPS_DEG = 1`、
`WHEEL_OFFSET_DEG = 0` 直接回传。该口径在固件中被 `FaultFlags` 位 20 明示为"临时直接 EPS 角度口径"。

### 为什么阻塞

Ackermann 里程计的航向变化是 `ω = v · tan(δ) / L`。δ 取的是**EPS 轴角**还是**前轮等效转角**，相差一个
转向系统传动比。若 EPS 装在转向柱、实际传动比为 1:15，则车辆转过 90° 而上位机航向只增长 6°。

关键在于**这个错误在数据上不可见**：航向在平滑增长，话题数据一切正常，只有车和地图对不上。

### 更要紧的一点：回传不能用来标定转角

**下发和回传走的是同一条链路的两个方向，用的是同一套常数。**核对上位机 `stm32_bridge.py` 与固件换算：

```
下发   angular.z = 5°  →  eps_raw = 5 / 0.1 = 50  →  字段 500000
回传   EPS raw 50      →  SteeringRaw = 50, ActualSteeringAngle = 50000  →  5°
```

两者严丝合缝。所以回传显示 5°，证明的只是"**EPS 轴上确实有 50 counts**"，**完全没有**证明"前轮转了
5°"。误差是**共模**的：命令 5°、回传 5°、实际 0.5°，三个数字可以完全自洽，没有任何一帧数据会露出破绽。
速度侧同理——回传 1.0 m/s 证明的是"电机确实在 3000 RPM"，不是"车在 1 m/s"。

**因此转角与速度的标定不能用回传比对，只能用地面真值（皮尺、量角器、地面标记）。**这是第 6 节两个
试验存在的理由。

### 需要下位机确认

1. EPS 的机械安装位置：转向柱 / 转向机输入 / 转向机输出 / 轮端？
2. `0x18F` 角度字段的物理含义：电机转子角、小齿轮角，还是方向盘角？
3. 从该角度到**前轮等效转角**的传动比。若已知，请给出数值与来源（图纸 / 实测 / Excel 矩阵），
   并说明置信度。
4. 编译期常量 `WHEEL_PER_EPS_DEG`、`WHEEL_OFFSET_DEG` 当前取值及其依据。
5. **转角零位**：前轮机械正前方时，`0x18F` 的读数是多少？机械零位与电气零位是否重合？
6. 左侧拉满的 +27.4° 是**机械限位**，还是上位机 `max_steering_angle_deg = 30.0` 限幅下的结果？
7. **EPS 厂家 Excel 矩阵标称 1 deg/count，实车确认却是 0.1 deg/count，正好差 10 倍。**这个 10 倍是在
   哪一层消掉的？固件补的 ÷10 是否**命令侧与回传侧都做了**？——一个"正好差 10 倍"的地方，通常意味着
   有人对单位的理解与另一处不一致，需要确认没有第二处同类错误。

### 请勿默认的两件事：来源必须独立

以下两个数字看起来互相印证，但都可能只是**同一个数字换了个地方出现**，不构成标定依据：

1. **`max_steering_angle_deg = 30.0`**（上位机 `config/vehicle.yaml`，标注 `NOT VERIFIED`）与下位机侧
   左满实测 **+27.4°**。两个数接近，但只有当 30.0 的来源独立于 `0x18F` 读数时才是旁证；若 30.0 本来
   就来自同一字段，则是循环论证。
2. **"原始 300 ↔ 现实 30°"这个实车确认是怎么确认的？** 如果是"命令 30°、读回 300"，那与上一节描述的
   共模问题性质相同，**同样是循环论证**；只有当"现实 30°"是拿量角器量了**前轮**（而不是读了 EPS
   寄存器）得到的，它才是真标定。请下位机说明当时的确认方法。

### 关闭条件

定半径圆试验（6.2）通过后，回填 `WHEEL_PER_EPS_DEG` / `WHEEL_OFFSET_DEG`，关闭
`LEGACY_STANDARD`、置 `VEH_FEEDBACK_STEER_CALIBRATED=1`，并清 `FaultFlags` 位 20。

## 2. 线速度系数（FaultFlags 位 19）—— 阻塞项

### 现状

`ActualSpeed` = 实测 RT49 RPM ÷ 3000。该 3000 来自控制侧常量 `VEH_RT49_RPM_PER_MPS`，
`METHOD = 1`、`VEH_FEEDBACK_USE_LEGACY_STANDARD = 1`、`CALIBRATED = 0`，从未与地面真值比对过。

### 这不只影响里程计

同一个 3000 也用在**下发方向**：上位机命令 1.0 m/s → 板子按 3000 换成 RPM → 驱动闭环去追。这一段是准的
（电机轴转速确实到了），但"电机 3000 RPM 是否等于车 1.0 m/s"由减速比与轮径决定，从未标定。

所以若该系数有偏差，**车辆实际速度与指令速度会成固定倍数关系**，而回传会报出与指令一致的数值（共模
误差，见第 1 节"回传不能用来标定转角"），上位机侧看不到任何异常。这直接影响到：

- `config/vehicle.yaml` 中 `max_forward_speed = 2.0`、`max_reverse_speed = -0.5`（均标注 `NOT VERIFIED`）
  ——**速度上限可能不是真的上限**；
- 导航/规划链路的速度约束、以及刹车距离的评估。

请下位机确认 3000 这个值是**当初实测标定**得到的，还是**沿用旧工程**的。若是后者，请一并说明其原始
来源。

### 需要下位机确认

1. RT49 上报的 RPM 是**电机轴**转速，还是**车轮轴**转速？
2. 若为电机轴，电机到车轮的减速比是多少？
3. **RT49 是几路反馈**：整车一个驱动、左右各一，还是四轮各一？`ActualSpeed` 是取了哪一路、
   取最大值，还是平均值？
   > **此条对里程计影响最大。** 若底盘为左右独立驱动或差速，单一速度值不能代表车体纵向速度；
   > 上位机必须知道它代表的是什么，才能决定是否可用以及如何写协方差。
4. 若已有可信的轮径与减速比，请启用 `METHOD = 2`（`v = RPM × 2π × r / (60 × gear_ratio)`）并给出
   `r`、`gear_ratio` 及其来源。上位机侧实测轮径为 **0.200 m**（车胎外径 0.400 m，
   `config/vehicle.yaml` 标注 VERIFIED，2026-09-15 实测）。
5. 请明确 `Core/upper_data.c` 中的 **24.068 减速比 / 0.105 m 轮径 / 1.205 m 轴距**属于哪套底盘。
   上位机侧文档将其记为"另一套备用口径"，需确认它与本台实车是否相关，或应彻底作废。

### 关闭条件

10 m 直线试验（6.1）通过后，关闭 `VEH_FEEDBACK_USE_LEGACY_STANDARD`、置 `CALIBRATED = 1`
（速度侧的确切宏名请下位机确认）并清 `FaultFlags` 位 19。

## 3. 符号约定 —— 阻塞项

里程计对符号错误的容忍度为零：速度符号错则倒车被记成前进；转角符号错则左右转弯的航向完全反向。
这类错误同样不会在单帧数据上暴露。

需要双方共同确认并书面记录：

1. `ActualSpeed` 正号 = 前进？
2. `ActualSteeringAngle` / `SteeringRaw` 正号 = **左转**（前轮逆时针）？

   > 上位机侧命令约定已实车验证：`/ackermann_cmd.angular.z > 0` 为左转，且从 Nav2 到 EPS 请求
   > **全链路无取反**（2026-09-17 实车：下发 +5°，前轮向左转）。
   > 若回传侧正号代表右转，上位机需要在**里程计内部**单独处理，**不得修改命令链路**。
3. 转角零位下 `SteeringRaw` 是否为 0。

### 注意：`Gear` 字段不能用于里程计

`Gear` 由实测 RPM 符号归一化得到，停车时为 `0`/未知，不是独立挡位传感器。里程计必须使用**带符号的
`ActualSpeed`**，不得按 `Gear` 决定运动方向。

## 4. 时间语义 —— 影响精度，不阻塞

### 现状

- `TimestampMs` 是"STM32 本控制周期汇总反馈的启动时间 ms"，既不是 CAN 采样时刻，也不是墙钟。
- `Counter` 为 u8，50 Hz 下约 **5.1 秒**回绕一次。
- 采样来自各设备异步 CAN：RT49 在 CAN2（500 kbps，反馈 `0x401`），EPS `0x18F` 在 CAN1（250 kbps，20 ms）。

### 需要下位机确认

1. 同一帧内 `ActualSpeed` 与 `ActualSteeringAngle` 的**采样时刻差上限**。若两者都在同一控制周期内刷新，
   请直接说明；若各自来自不同 CAN 且未对齐，请给出典型差值。
2. 文档 5.5 提到 `g_vehicle_status` 中保存了各设备的 `sample_ms`，是否可以纳入回传，或至少给出其定义？
3. **重启的区分方式**：上位机如何判断收到的 `TimestampMs` 变小是因为 STM32 重启，还是 u32 的 49.7 天
   回绕？是否可以增加一个开机计数（boot counter）字段，或直接使用当前 Reserved 的三个字节
   （偏移 49..51）？若使用 Reserved，请在接口说明中同步更新。
4. `Counter` 按"发送尝试"递增、缺口不代表故障——已理解，**无需改动**。

### 对里程计的影响

低速下时间差带来的误差小于尺度误差，因此**不阻塞**。但积分需要可靠的 dt；在缺少上述信息前，上位机只能用
本机接收时刻积分，精度和协方差都要相应放宽。

## 5. 累计编码器（ValidFlags 位 0）—— 非阻塞

### 现状

`DriveEncoderCount`（i64）当前恒为 0，位 0 保持清除。接口说明明确"三协议未提供累计计数""不得积分 RPM
冒充编码器"。

### 说明

里程计**不依赖**该字段——对速度积分是标准做法。因此此项**不阻塞**开发。但若可提供，收益是：

- 位移可由计数直接差分，不再依赖速度系数标定；
- 可与速度积分互相对账，这是打滑 / 丢脉冲**唯一**的检测手段。

### 需要下位机确认

RT49 或其他驱动是否可读出真实累计位置计数？EPS 内部是否有里程或累计转角？若短期确实没有来源，请明确
告知，上位机将按"无冗余源、无打滑检测"实现，并把该限制记录在案。

## 6. 联合标定试验

以下两个试验需在**实车**上进行，需要下位机工程师在场读取 Keil 侧 `g_vehicle_status` 做同步比对。
上位机侧的两个工具都只监听、不下发任何控制帧：

```bash
./scripts/show_feedback.py        # 实时解码打印 56 字节回传
./scripts/start_vehicle.sh status # 只起 stm32_status 接收节点
```

### 6.1 10 m 直线试验（定速度系数）

1. 地面标出 10 m 直线，起点终点做标记。
2. 恒定速度指令（建议 0.5 m/s）行驶，记录上位机侧 `ActualSpeed` 序列与接收时间。
3. 卷尺量实际行驶距离，与 `∫v dt` 对比。
4. 前进、倒车各做 3 次；倒车同时验证速度符号（第 3 节）。
5. 由实测比值反推真实系数并回填固件，清 `FaultFlags` 位 19。

**验收标准**：3 次前进的距离偏差一致性 < 2%，且积分距离与实际距离偏差 < 2%。

### 6.2 定半径圆试验（定转角映射与轴距）

1. 固定转角指令（建议 15°），低速行驶整圈，闭合后停车。
2. 地面测量**圆形轨迹的直径**——沿**后轴中心**的轨迹测量，不是车身外缘。上位机里程计参考点为
   `rear_axle_link`。
3. 由 `R = L / tan(δ)` 反解 δ 的等效前轮角。结合上位机已知 `L = 0.960 m`（VERIFIED，2026-09-15 实测）
   可同时检验轴距取值是否与回传口径自洽。
4. 至少做 **15°** 与 **27°**（接近满舵）两档。

   > **必须做两档的原因**：若两档反解出的比例不一致，说明存在机械非线性（EPS 轴角与前轮角不是简单
   > 比例关系）。此时里程计需按查表而非单一比例处理，这一点必须落在文档里，否则后续一定会有人
   > 用一个系数去套整个范围。
5. 左转、右转各做一次，验证符号对称性（第 3 节）。
6. 回填 `WHEEL_PER_EPS_DEG` / `WHEEL_OFFSET_DEG`，清 `FaultFlags` 位 20。

**验收标准**：两个方向、两档转角下，按标定值算出的航向变化与实际转弯角度偏差 < 3°。

## 7. 标定完成前上位机侧的行为（供参考）

- **不发布** `odom → base_link` TF。该 TF 当前归 LIDAR/IMU 定位链路所有，两个发布者会冲突。
