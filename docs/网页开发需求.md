> **项目**：汉宇晨星二代巡检机器人设计研发  
> **版本**：V1.0（依据所提供的 0929 版合同及技术附件整理）

> **重要声明**：本文件是**开发实施清单，不是合同变更文件**。最终验收范围以双方正式签署版本及书面确认事项为准。开发阶段排序不等于免除合同义务。

## 一、适用范围、优先级与交付原则

### 1.1 对照资料

| 简称 | 原始资料 | 主要依据 |

| **C** | 《0929技术开发（委托）合同-律师反馈v4》 | 第十二条（交付）、第十三条（验收）、附件一第18项（本机功能）、第19项（接口）、第20项（触摸屏）、第21项（远端平台）、附件三（技术指标）和附件四（交付物） |

| **S** | 《0929附件五_技术标准和规范(1)》 | 第2、4～12章及附表 A1～A18：平台接口、安全闭环、地图、任务、告警、日志、交付等 |

> 术语约定：**远端平台**指在浏览器或 Qt 桌面运行的管理软件；**机器人端**指 ROS2 与底盘、感知、导航、控制相关的软件；**本体屏**指安装在机器人上的安卓/鸿蒙等触摸屏界面。三者不可简单合并为同一个页面。

### 1.2 标记说明

- **【硬性】**：合同/技术标准明确要求的功能，或完成明确要求所必需的支撑能力；验收前必须落实。对具体按钮/字段的实现方式可调整，但功能不可缺失。
- **【实现】**：文档未指定具体界面或技术形态，但为落地、集成、测试而建议采用的工程实现；可以用等效方案替代。
- **【增强】**：提升使用体验、效率或可维护性的功能，**不得冒充合同强制项**，可在基本验收闭环稳定后开发。
- **【分级】**：合同附件一/技术附件提到的第二、第三优先级能力，应纳入项目总体需求；**具体实施批次、是否参与首台样机当期验收须双方书面确认**。
- **阶段 S0** 基础架构与接口；**S1** 最小联动验收闭环；**S2** 完整业务能力；**S3** 稳定性、安全及验收交付；**S4** 可选扩展。
- **优先级 P0**：直接影响核心功能与验收；**P1**：完整业务能力及辅助验收；**P2**：增强项。阶段编号是建议的**实施顺序**，并非合同里写明的项目里程碑。

### 1.3 平台的核心闭环

`地图/区域配置 → 巡检点设置 → 任务创建和下发 → 机器人自主导航 → 到点拍摄/识别/播报 → 结果/告警回传 → 人工处置与复检 → 日志与报告留存`

**技术边界**：LIO-SAM、NDT、Hybrid A*、NeuPAN、安全避障、硬件急停和低电回充核心逻辑在机器人端实现。平台承担**配置、下发、可视化、结果归档和诊断**；即使网络中断，机器人仍应按本地安全策略继续或安全停止（R-1、R-7；S-2、S-10）。

## 二、S0：基础架构、数据模型和机器人通信（先做）

**阶段目标**：让远端平台能真实、安全地与 ROS2 机器人连接，具备可靠的命令、状态、事件和日志通道。此阶段不以页面美观为目标。

- [ ] **S0-01｜系统分层与部署方案【硬性/P0】**：区分前端、业务后台、机器人通信桥接、机器人本地控制与触摸屏应用，明确各自职责及离线边界。**验收检查**：提交架构图，并能说清哪些功能断网仍可运行。**依据**：R-1、R-7；S-2、S-12。
- [ ] **S0-02｜ROS2 接口清单【硬性/P0】**：梳理使用的 Topic、Service、Action、TF 与消息类型，明确状态上报、导航任务、设备健康、故障和巡检结果各自的来源。**验收检查**：接口清单与实际机器人节点逐项对应。**依据**：C-附件一19；S-2、S-12。
- [ ] **S0-03｜平台通信桥接服务【实现/P0】**：将 ROS2 消息转换为远端可用的 API/实时消息，避免浏览器直接依赖底盘驱动。可采用 REST+WebSocket、Qt 原生接口等**等效方案**。**验收检查**：能下发任务、查询状态和订阅事件。**依据**：C-附件一19、21；S-10。
- [ ] **S0-04｜统一设备与机器人标识【实现/P0】**：为机器人、地图、巡检点、任务、资产、告警、日志设唯一 ID，以便跨页面追踪。**验收检查**：从某条告警可关联其机器人、任务、点位与证据。**依据**：S-7、S-9、S-10。
- [ ] **S0-05｜任务/事件/故障统一消息结构【硬性/P0】**：规范消息 ID、机器人 ID、任务 ID、类型、时间戳、状态、错误码、载荷与版本。JSON 可作为推荐表示，但不是唯一合规方式。**验收检查**：各模块按统一结构收发及解析数据。**依据**：C-附件一19；S-10、S-12。
- [ ] **S0-06｜控制指令回执与去重【硬性/P0】**：对任务启动、暂停、恢复、取消、回充等指令返回已接收/执行中/成功/失败及原因；防止网络重发导致重复执行。**验收检查**：重复点击或重发后任务不会被重复创建。**依据**：S-9、S-10。
- [ ] **S0-07｜机器人连接与心跳【硬性/P0】**：接收 5G/Wi-Fi 通信状态、最后心跳、设备可达性和数据新鲜度。**验收检查**：断连后平台及时显示失联，恢复后自动更新状态。**依据**：C-附件一19；S-8、S-10。
- [ ] **S0-08｜状态机与指令约束【硬性/P0】**：统一空闲、执行中、暂停、异常、回充、充电等状态及允许的操作，避免在充电、急停或失定位时执行普通移动。**验收检查**：非法状态下指令被明确拒绝并提示原因。**依据**：S-6、S-8～10。
- [ ] **S0-09｜地图坐标与时间同步【硬性/P0】**：约定地图坐标系、机器人位姿、巡检点姿态、时间戳、时区和 TF 变换，避免位置偏移与告警时间错乱。**验收检查**：平台显示点位与机器人实地位置相符，事件时间顺序正确。**依据**：S-2～4。
- [ ] **S0-10｜基础数据持久化【实现/P0】**：持久保存地图元数据、区域、巡检点、任务模板、执行记录、告警、资产和设备状态快照。**验收检查**：平台/后台重启后数据不丢失。**依据**：S-2、S-7、S-9、S-10。
- [ ] **S0-11｜离线缓存与恢复补传【硬性/P0】**：机器人网络不可用时本地缓存重要任务、状态、事件与故障；重连后按可靠方式补传、去重并记录补传结果。**验收检查**：断网期间产生的事件在重连后可查询，不影响本地安全闭环。**依据**：R-1、R-7；S-2、S-10。
- [ ] **S0-12｜接口身份认证与传输安全【硬性/P0】**：为远端访问建立身份认证、加密传输、参数/配置校验和控制指令确认，限制未授权控制。**验收检查**：未登录或无权的客户端无法控制机器人，异常参数被拒绝。**依据**：R-7；S-10。
- [ ] **S0-13｜运行日志与接口错误码【硬性/P0】**：记录指令调用、状态变化、接口失败、连接中断及机器人错误原因。**验收检查**：能凭任务 ID/时间范围找到一次失败的原因与日志。**依据**：C-附件一19；S-2、S-8、S-12。
- [ ] **S0-14｜仿真/假数据联调模式【实现/P1】**：机器人未接入时，通过模拟状态、任务和告警验证 UI；必须与真实数据模式明确区分。**验收检查**：可切换到真实机器人且不会将模拟数据作为验收证据。**依据**：工程建议。
- [ ] **S0-15｜开发环境与可复现部署【硬性/P0】**：固定前后端、ROS2 桥接、依赖、配置、启动命令和版本。**验收检查**：新环境按文档可重新编译和启动。**依据**：C-第十二条；S-12。

**S0 退出条件**：真实机器人可连接；任务指令有回执；地图位姿与状态可查询；断网/重连能正确处理；接口与部署文档有初稿。

## 三、S1：最小可验收业务闭环（优先打通）

### 3.1 运行总览 / 运行大屏

- [ ] **S1-01｜机器人在线卡片【硬性/P0】**：显示机器人编号、在线/离线、当前运行模式和最后上报时间。**验收检查**：状态与真机连接变化一致。**依据**：C-附件一21；S-8、S-10。
- [ ] **S1-02｜实时二维地图【硬性/P0】**：在运行大屏加载当前二维占据栅格地图，正确对应地图版本。**验收检查**：地图与现场通道、障碍结构吻合。**依据**：C-附件一21；S-4、S-10。
- [ ] **S1-03｜机器人实时位置/朝向【硬性/P0】**：在地图上标注机器人位姿及朝向，状态过期时明显标识。**验收检查**：机器人移动时地图标记同步更新。**依据**：S-4、S-10。
- [ ] **S1-04｜运动轨迹和规划路线【硬性能力+实现/P0】**：显示已走轨迹、当前目标、规划路径；规划路径的可视化为推荐实现，便于验证。**验收检查**：到点执行时可回看实际路径；机器人本体屏也需显示本体轨迹。**依据**：C-附件一20；S-4～5。
- [ ] **S1-05｜任务进度总览【硬性/P0】**：显示任务名称、当前巡检点、已完成/剩余点数、执行状态和失败原因。**验收检查**：后台任务每个状态变化在界面可见。**依据**：S-9～10。
- [ ] **S1-06｜电量与充电状态卡片【硬性/P0】**：显示剩余电量、低电状态、充电/非充电/回充状态。**验收检查**：BMS 状态变化实时同步。**依据**：C-附件一21；S-8～10。
- [ ] **S1-07｜告警概览与跳转【硬性/P0】**：展示最新异常、等级、类型、点位和发生时间，能进入详情。**验收检查**：触发异常后大屏出现对应记录。**依据**：C-附件一18、21；S-7、S-10。
- [ ] **S1-08｜关键故障与安全状态【硬性/P0】**：显示定位丢失、急停、近场停车、传感器故障、运动受阻等安全信息。**验收检查**：故障注入时可看到明确状态及原因。**依据**：S-6、S-8。
- [ ] **S1-09｜大屏布局与异常提示【实现/P1】**：让地图、任务、电池、告警同屏可读，断线、空数据、加载失败有提示。**验收检查**：现场演示无需频繁切换才能确认机器人总体运行。**依据**：C-附件一21（运行大屏）。

### 3.2 地图与区域管理

- [ ] **S1-10｜发起/管理建图任务【硬性/P0】**：平台可管理实施阶段的园区及楼宇建图流程，显示建图进度/状态；实际 LIO-SAM 建图在机器人端进行。**验收检查**：可完成真实场景建图流程并取得地图成果。**依据**：C-附件一21；R-2；S-4。
- [ ] **S1-11｜三维点云与二维占据地图成果【硬性/P0】**：接收并管理机器人端建图产物，保证导航使用的二维地图与三维地图对应。三维点云不要求必须在网页高帧率渲染。**验收检查**：两类地图文件可保存、重新加载和用于定位。**依据**：R-2；S-4。
- [ ] **S1-12｜地图保存、加载与切换【硬性/P0】**：地图具有名称、范围、版本、适用楼宇/园区，支持选中并加载。**验收检查**：机器人能按选择的地图重新定位并导航。**依据**：R-2；S-4。
- [ ] **S1-13｜运行区域划定【硬性/P0】**：在地图上画出允许机器人工作的区域并保存配置。**验收检查**：机器人不会接受超出允许范围的普通导航目标。**依据**：C-附件一21；S-4～5。
- [ ] **S1-14｜禁行区与虚拟墙【硬性/P0】**：添加、编辑、删除禁行区/虚拟墙，阻止全局路径穿过禁止区域。**验收检查**：修改并发布后重新规划的路线避开该区域。**依据**：R-2；S-4～5。
- [ ] **S1-15｜限速区【硬性/P0】**：配置特殊区域速度上限（人员密集区、狭窄通道、充电区等）。**验收检查**：机器人进入区域后按实际控制侧策略限速。**依据**：R-2；S-4～5。
- [ ] **S1-16｜充电区和充电目标点【硬性/P0】**：在地图中标定充电区域、目标姿态及机器人回充需要的关联信息。**验收检查**：回充指令能找到目标区域。**依据**：S-4、S-9。
- [ ] **S1-17｜区域配置发布与校验【硬性能力+实现/P0】**：将编辑过的地图与区域配置校验后同步给机器人，防止无效多边形、冲突规则或过期地图直接生效。**验收检查**：无效配置有错误提示，有效配置实际生效。**依据**：S-4、S-10。
- [ ] **S1-18｜地图版本与生效状态【硬性/P0】**：显示当前使用的地图版本及机器人端加载版本，避免平台与机器人使用不同地图。**验收检查**：可根据任务追溯当时使用的地图版本。**依据**：R-1～2；S-11。
- [ ] **S1-19｜地图质量检查记录【硬性/P0】**：保留轨迹连续性、重影/错层、关键通道、室内外过渡等建图检查结果。**验收检查**：缺陷地图不得作为最终验收地图发布。**依据**：S-4。
- [ ] **S1-20｜多建筑/楼层组织【硬性范围+实现/P1】**：按园区、楼宇、楼层组织地图和巡检点；跨楼层切换应结合具体现场能力与锚点方案。**验收检查**：能定位所需园区/楼宇地图；是否需要实际跨楼层自主通行按现场验收范围确认。**依据**：C-附件一21；R-2。

### 3.3 巡检点与业务资产

- [ ] **S1-21｜地图点选创建巡检点【硬性/P0】**：在地图上指定位置与朝向，并填写编号、名称、用途。**验收检查**：保存后在地图与点位列表中均能看到。**依据**：C-附件一21；S-4、S-9。
- [ ] **S1-22｜巡检点查询、编辑、删除【硬性/P0】**：支持名称/编号查询、位置调整和删除，同时处理已关联任务。**验收检查**：对被引用的点位给予冲突提示，防止任务无效。**依据**：C-附件一21。
- [ ] **S1-23｜巡检点动作配置【硬性/P0】**：给点位配置停车、拍照、识别项目、语音播报等动作及先后顺序。**验收检查**：机器人到点后依次执行相应动作。**依据**：C-附件一19、21；S-9。
- [ ] **S1-24｜到点确认【硬性/P0】**：只有机器人报告抵达、定位可靠并停车后才触发需要稳定拍摄的巡检动作。**验收检查**：未达到到点条件时不提前记录正常巡检完成。**依据**：S-9。
- [ ] **S1-25｜点位地图关联与版本一致性【实现/P0】**：巡检点与地图版本绑定，地图更新后检查点位是否偏移或不可达。**验收检查**：无效点位不能直接生成正常任务。**依据**：S-4、S-9、S-11。
- [ ] **S1-26｜设施/设备资产台账【硬性/P0】**：登记消防栓、消防柜、灭火器、防火门、紧急指引灯等资产的 ID、名称、类型和位置。**验收检查**：巡检结果与具体设施绑定。**依据**：C-附件一18；S-7、S-10。
- [ ] **S1-27｜资产关联巡检点【硬性/P0】**：为每项资产关联适合观察的点位和巡检动作，便于复检及异常回溯。**验收检查**：通过资产能查到对应点位及历史结果。**依据**：S-7。
- [ ] **S1-28｜设施基准照片及参考状态【硬性能力+实现/P1】**：为需做状态/外观比对的设施保留基准图片和正常状态说明。**验收检查**：异常详情可显示比对依据。**依据**：R-4；S-7。

### 3.4 巡检任务创建、调度与执行

- [ ] **S1-29｜常规巡检任务模板【硬性/P0】**：配置固定巡检点序列、到点动作、任务名称和启用状态。**验收检查**：模板可多次生成有效巡检执行实例。**依据**：C-附件一21；S-9。
- [ ] **S1-30｜常规任务周期执行【实现/P1】**：支持按日/周/指定时间等方式自动产生任务，作为常规巡检的一种可用实现。**验收检查**：到时按配置下发，并保留触发记录。**依据**：C-附件一21（常规巡检）。
- [ ] **S1-31｜指定巡检任务【硬性/P0】**：人工选择一个或多个巡检点，立即或指定时机下发一次任务。**验收检查**：机器人只执行本次指定点位。**依据**：C-附件一21。
- [ ] **S1-32｜到点动作串联【硬性/P0】**：将“移动 → 拍摄 → AI 识别 → 语音/其他动作 → 上报”组成可跟踪的动作序列。**验收检查**：执行记录可查看各步骤结果。**依据**：C-附件一19；S-9。
- [ ] **S1-33｜任务下发与指令确认【硬性/P0】**：任务从平台发送到机器人后显示接收/拒绝及原因，不将网络发送成功误认为任务成功。**验收检查**：离线机器人接不到任务时有明确结果。**依据**：C-附件一19；S-10。
- [ ] **S1-34｜任务状态全过程追踪【硬性/P0】**：至少区分待执行、执行中、已暂停、已完成、失败、已取消等状态。**验收检查**：状态、当前点位和最后更新时间一致。**依据**：S-9。
- [ ] **S1-35｜任务暂停【硬性/P0】**：暂停当前任务并让机器人按本地安全规则停止当前移动及可暂停的动作/播报。**验收检查**：页面可明确显示暂停请求与暂停生效状态。**依据**：C-附件一21；S-9。
- [ ] **S1-36｜任务恢复【硬性/P0】**：恢复已暂停任务，并根据机器人安全与定位状态从合适位置继续。**验收检查**：正常情况下无需新建任务即可接着执行，异常状态会拒绝恢复。**依据**：C-附件一21；S-9。
- [ ] **S1-37｜任务取消与安全退出【硬性/P0】**：人工终止任务，停止未执行动作并留存取消原因。**验收检查**：取消后机器人不继续执行后续巡检点。**依据**：S-9。
- [ ] **S1-38｜任务失败重试【硬性/P0】**：对导航失败、动作失败和暂时性接口失败按策略重试，次数受控。**验收检查**：可看到重试次数、原因与最终结果。**依据**：C-附件一19；S-9。
- [ ] **S1-39｜任务异常分支【硬性能力+实现/P0】**：对长时间阻塞、路径不可达、定位丢失、低电等情况采取等待、重规划、跳过、停车或请求人工处理。**验收检查**：每种异常具有可解释的状态和记录。**依据**：R-2；S-5、S-8～9。
- [ ] **S1-40｜任务与地图/点位关联【实现/P0】**：每个任务保存所用地图、巡检点、任务模板与机器人信息。**验收检查**：历史记录可复现任务配置。**依据**：S-9、S-11。
- [ ] **S1-41｜任务执行历史【硬性/P0】**：按任务 ID 查看开始结束时间、点位结果、异常、失败原因。**验收检查**：完成/失败/取消任务都能查到结果。**依据**：S-2、S-9。
- [ ] **S1-42｜任务列表检索【实现/P1】**：按机器人、任务类型、时间、状态和结果筛选记录。**验收检查**：可快速定位特定验收演示任务。**依据**：S-2、S-9（追溯能力）。

### 3.5 巡检结果与基础告警

- [ ] **S1-43｜统一巡检结果入库【硬性/P0】**：保存到点动作的完成状态、识别结果、采集时间、点位和关联任务 ID。**验收检查**：执行一个任务后能逐点查看结果。**依据**：S-7、S-9。
- [ ] **S1-44｜异常事件实时接收【硬性/P0】**：机器人端确认异常后向平台推送事件，平台同步展示。**验收检查**：人工构造真实可检出的异常场景后出现对应告警。**依据**：C-附件一18；S-7、S-10。
- [ ] **S1-45｜告警分类和等级【硬性能力+实现/P0】**：区分火灾烟雾、积水、堵塞、安全帽、设施异常、入侵、设备故障等，标示风险等级。**验收检查**：不同类别可区分并检索。**依据**：C-附件一18、附件三；S-7～8。
- [ ] **S1-46｜告警详情与证据【硬性/P0】**：展示图像/热红外/温度（依事件类型而定）、时间、机器人、地图位置、资产和任务关联。**验收检查**：事件详情足以复核异常发生的时间、地点、证据。**依据**：S-7。
- [ ] **S1-47｜地图告警定位【实现/P0】**：将告警以图标/标记呈现在对应地图位置，并能打开事件详情。**验收检查**：点击大屏告警可定位到对应点位。**依据**：S-7、S-10（事件与位置管理）。
- [ ] **S1-48｜“无法确认”识别状态【硬性/P0】**：对图像质量不足、遮挡等情况保留无法确认状态，而不是当作正常或确定异常。**验收检查**：质量不足样例在结果中显示不确定性。**依据**：S-3、S-7。
- [ ] **S1-49｜告警去重与持续状态【硬性能力+实现/P1】**：按时序、位置、同目标规则抑制连续重复告警，记录首次/最近出现时间。**验收检查**：持续异常不会无意义地产生大量独立事件。**依据**：S-7。
- [ ] **S1-50｜告警查询与记录留存【硬性/P0】**：按时间、类别、机器人和位置检索历史告警，保留证据关联。**验收检查**：平台重启后仍能检索历史事件。**依据**：S-2、S-7、S-10。
- [ ] **S1-51｜告警确认/处理状态【实现/P1】**：支持人工确认、记录处理备注、标记待复检/已关闭，形成管理闭环。**验收检查**：事件操作有操作人及时间记录。**依据**：工程建议，服务于 S-7 复检要求。

### 3.6 设备与 BMS 最小控制台

- [ ] **S1-52｜机器人设备详情【硬性/P0】**：查看机器人编号、运行状态、软件版本、在线状态和当前任务。**验收检查**：数据来自机器人而非写死的演示页面。**依据**：C-附件一21；S-8、S-10。
- [ ] **S1-53｜实时 SOC 电量【硬性/P0】**：显示电池剩余电量百分比以及数据更新时间。**验收检查**：与实际 BMS/机器人上报一致。**依据**：C-附件一18、21；S-8。
- [ ] **S1-54｜BMS 关键状态【硬性/P0】**：展示充电、放电、低电、保护/故障等状态；电压、电流、温度等字段视 BMS 实际支持情况接入。**验收检查**：相关状态变化能够显示并留存。**依据**：C-附件一21；S-8～9。
- [ ] **S1-55｜低电阈值配置【硬性/P0】**：支持自定义低电量告警阈值，默认值 **20%**，并区分预警与强制回充策略。**验收检查**：修改阈值后真实告警/回充策略按配置触发。**依据**：C-附件三；S-9。
- [ ] **S1-56｜低电与电池故障告警【硬性/P0】**：接收低电、异常充电、BMS 保护等状态并展示原因。**验收检查**：触发电量/故障测试后可在告警页查询。**依据**：C-附件一18；S-8～9。
- [ ] **S1-57｜设备健康总览【硬性/P0】**：显示激光雷达、IMU、相机、底盘/电机、通信等健康或数据新鲜度状态。**验收检查**：关闭指定传感器后平台可见异常。**依据**：C-附件一18、19；S-3、S-8。

**S1 退出条件（完成“第一条链路”）**：配置真实地图/区域 → 建巡检点 → 创建常规或指定任务 → 机器人导航并到点采集 → 平台展示结果/告警/电量 → 暂停恢复 → 查询任务与事件记录；全过程以真实机器人联调证据为准。**完成 S1 不代表满足全部最终验收要求。**

## 四、S2：补齐合同要求的专项业务能力（最终验收前必须评审完毕）

**阶段目标**：不仅能完成一次巡检演示，还要覆盖合同中涉及的业务识别、引导讲解、任务干预、BMS 自主回充、本体屏及故障诊断。这里包含若干机器人端能力，平台需提供对应的**配置、状态、记录、演示和追溯入口**，不能用“有按钮”替代真机实现。

### 4.1 多模态识别结果展示与业务处置

- [ ] **S2-01｜火焰与烟雾告警【硬性/P0】**：接收“可见光 AI + 热红外温度 + 时序确认”的识别结果，展示火/烟类型、位置、时间、图像、热图或温度证据，并记录机器人后续动作。**验收检查**：真实场景测试可查询完整证据，识别效果按附件一/附件三适用指标验证。**依据**：C-附件一18；R-4；S-7。
- [ ] **S2-02｜积水识别【硬性/P0】**：展示地面积水区域、现场照片、位置和告警记录，必要时关联临时风险区域。**验收检查**：积水触发后自动保存图像并上报。**依据**：C-附件一18；S-7。
- [ ] **S2-03｜漏水/滴水识别【硬性/P0】**：接收基于时序变化确认的漏水或滴水结果，展示证据、发生位置和时间。**验收检查**：事件按类型记录，不与一般积水混淆。**依据**：C-附件三；R-4；S-7。
- [ ] **S2-04｜通道异物与堵塞【硬性/P0】**：展示通道位置、几何占用/通行状态、现场图片及机器人采取的停车、绕行、重规划动作。**验收检查**：模拟堵塞后可见告警及任务状态；障碍移除后的解除记录可追溯。**依据**：C-附件一18；S-7。
- [ ] **S2-05｜未戴安全帽识别【硬性/P0】**：展示人员检测结果、标注图、位置、时间、提醒是否已播放；遮挡等证据不足时显示无法确认。**验收检查**：确认风险后机器人按配置进行语音提醒且不影响避障。**依据**：C-附件一18；S-7。
- [ ] **S2-06｜消防栓/消防柜/灭火器识别【硬性/P0】**：关联资产 ID，对缺失、遮挡、位置变化或明显外观异常给出事件和证据。**验收检查**：从资产详情可打开本次异常与历史巡检结果。**依据**：C-附件一18、附件三；S-7。
- [ ] **S2-07｜防火门和紧急指引设施识别【硬性/P0】**：展示常开/常闭门状态及紧急指引灯等设施异常；保留正常基准与现场证据。**验收检查**：能区分设施类型和异常原因。**依据**：C-附件一18、附件三；S-7。
- [ ] **S2-08｜设施整改后同点复检【硬性/P1】**：从异常资产快速定位原巡检点，创建复检任务并比对整改前后结果。**验收检查**：同一资产可形成“异常—整改—复检”记录链。**依据**：S-7。
- [ ] **S2-09｜非法闯入事件【硬性/P0】**：依据机器人端人员跟踪结果、地图限制区域和生效时间接收/展示非法进入告警。**验收检查**：对指定区域的违规进入可生成带时间位置的事件，不以人脸识别作为入侵判定的必要前提。**依据**：C-附件三；R-4；S-7。
- [ ] **S2-10｜陌生人员/人脸识别【分级/P1】**：支持后续接入授权特征库比对结果，展示确认、未知、图像质量不足等状态；限制图像和身份数据的访问。**验收检查**：若纳入当期验收，则提供授权样本、识别日志和合规证明；否则保留书面范围确认。**依据**：C-附件一18（第二优先级）；R-4；S-7。
- [ ] **S2-11｜货位与货物异常【分级/P1】**：关联固定巡检点/固定拍摄视角，展示货物数量、轮廓、堆放异常及倾倒风险，保留基准图和当前图。**验收检查**：若纳入当期验收，能够展示比对证据与现场实测记录；否则保留书面范围确认。**依据**：C-附件一18（第三优先级）；R-4；S-7。
- [ ] **S2-12｜人群聚集与异常奔跑【硬性业务能力/P1】**：接收由人员跟踪、密度、速度和持续时间形成的异常事件，并展示区域和阈值。**验收检查**：事件能够在适用场景下复现并记录。**依据**：R-4；S-7。
- [ ] **S2-13｜异常无主物品【硬性业务能力/P1】**：展示长时间无人关联物品的检测区域、近景/全景和持续时间。**验收检查**：形成有位置和证据的事件；适用场景、阈值应结合现场确认。**依据**：R-4；S-7。
- [ ] **S2-14｜降雨及避雨状态【硬性业务能力/P1】**：显示户外雨情识别、避雨动作、任务暂停和恢复状态。**验收检查**：按现场策略可记录雨天暂停、前往避雨点和恢复过程；IP65 为本体防护指标，不能通过界面证明。**依据**：C-附件三；R-4；S-7。
- [ ] **S2-15｜业务识别阈值/策略查看【硬性能力+实现/P1】**：将已配置的事件阈值、连续帧确认规则、区域生效条件等以版本化方式呈现；允许修改的项目须进行权限和范围校验。**验收检查**：记录每次参数修改及生效版本，不能绕过端侧安全条件。**依据**：S-7、S-11。
- [ ] **S2-16｜异常触发后的机器人动作记录【硬性/P0】**：展示确认异常后机器人采取的停车、提醒、观察、绕行或撤离等结果。**验收检查**：告警与机器人状态变化可按时间线对应。**依据**：C-附件一18；S-6～8。

### 4.2 引导讲解与一次性强制任务

- [ ] **S2-17｜讲解内容管理【硬性/P0】**：新增、编辑、停用讲解主题及文字内容，指定需要播报的地点或场景。**验收检查**：保存后的讲解内容可关联到执行任务。**依据**：C-附件一21；S-10。
- [ ] **S2-18｜讲解动作/语音播报编排【硬性/P0】**：配置讲解流程中移动、停靠、动作和语音播报的顺序及目标。**验收检查**：机器人按实际下发的序列执行。**依据**：C-附件一19、21；S-9。
- [ ] **S2-19｜单次强制任务下发【硬性/P0】**：支持引导解说等一次性强制任务，区别于周期巡检，只执行本次。**验收检查**：任务完成后不自动再次重复执行。**依据**：C-附件一21。
- [ ] **S2-20｜任务优先级与抢占规则【硬性能力+实现/P0】**：明确一次性强制任务如何与正在运行的普通巡检协调；任何业务任务都不得越过急停、安全故障和强制回充。**验收检查**：冲突时平台提示调度结果，机器人遵守本地安全优先级。**依据**：C-附件一21；S-6、S-9～10。
- [ ] **S2-21｜播报进度与状态【硬性/P0】**：显示文字、当前播报片段、播报中/暂停/完成/失败状态。**验收检查**：与机器人端实际播放同步。**依据**：C-附件一20～21。
- [ ] **S2-22｜播报暂停与恢复【硬性/P0】**：远端暂停正在执行的语音播报，再恢复到约定位置或阶段。**验收检查**：任务暂停/恢复覆盖语音，不仅覆盖底盘移动。**依据**：C-附件一21。
- [ ] **S2-23｜动作暂停与恢复【硬性/P0】**：控制讲解或巡检过程中的非移动动作（例如拍摄、云台动作、播报）按支持的粒度暂停/恢复。**验收检查**：界面展示机器人确认后的动作实际状态。**依据**：C-附件一21。
- [ ] **S2-24｜讲解任务历史【硬性能力+实现/P1】**：记录发起人、讲解内容版本、执行时间、机器人和完成/失败原因。**验收检查**：单次任务可独立查询和复盘。**依据**：S-2、S-9。

### 4.3 机器人本体触摸屏（**独立交付**）

- [ ] **S2-25｜安卓/鸿蒙等本体端部署【硬性/P0】**：以适配实际触摸屏系统的应用或等效界面运行，并与原有一代交互兼容；尽量在同一常驻应用内完成，不依赖切换 App。**验收检查**：设备启动后直接进入可使用的常驻界面。**依据**：C-附件一12、20。
- [ ] **S2-26｜本体栅格地图【硬性/P0】**：在机器人触摸屏显示当前二维栅格地图与机器人位置。**验收检查**：屏幕地图与当前运行地图一致。**依据**：C-附件一20。
- [ ] **S2-27｜本体运动轨迹【硬性/P0】**：在本体地图上绘制实际行进轨迹，必要时清晰显示当前位置。**验收检查**：机器人行进后轨迹可见。**依据**：C-附件一20。
- [ ] **S2-28｜讲解文字同步【硬性/P0】**：引导讲解时同步显示相应文字段落或当前讲解内容。**验收检查**：屏幕内容与语音讲解相符。**依据**：C-附件一20。
- [ ] **S2-29｜低功耗卡通待机形象【硬性/P0】**：无交互或任务时显示指定卡通待机界面，并考虑屏幕功耗与可唤醒性。**验收检查**：正常进入待机状态且可以唤醒使用。**依据**：C-附件一20。
- [ ] **S2-30｜语音唤醒与单屏功能界面【硬性/P0】**：语音唤醒后显示单屏交互功能，避免跨应用跳转。**验收检查**：现场语音唤醒后进入指定界面。**依据**：C-附件一18、20。
- [ ] **S2-31｜端侧语音理解和执行【硬性/P0】**：接收本地语音指令，完成允许范围内的任务控制或交互反馈；不因远端断连失去约定的端侧功能。**验收检查**：现场验证典型语音指令的识别和执行。**依据**：C-附件一18；R-7。
- [ ] **S2-32｜本体工作/任务/巡检状态【硬性/P0】**：显示当前运行状态、任务、关键巡检信息及必要的引导内容。**验收检查**：工作过程中屏幕状态与机器人一致。**依据**：S-10。
- [ ] **S2-33｜界面故障与导航隔离【硬性/P0】**：本体屏进程崩溃、刷新或卡顿时，不影响机器人导航、避障和安全停车。**验收检查**：人为终止界面进程后安全核心功能仍按设计运行。**依据**：R-7；S-10、S-12。

### 4.4 自主充电、机器人健康与故障处理

- [ ] **S2-34｜自主回充指令入口【硬性/P0】**：远端可请求机器人回充，但实际回充由机器人端自主导航与充电对接控制完成。**验收检查**：机器人接到合法指令后进入回充状态。**依据**：C-附件一21、附件三；S-9。
- [ ] **S2-35｜低电自动回充状态跟踪【硬性/P0】**：显示低电预警、强制回充、导航到充电区、对接中、充电中、完成/失败等阶段。**验收检查**：一次完整回充过程可按时间线查看。**依据**：C-附件三；S-9。
- [ ] **S2-36｜回充失败及有限重试【硬性/P0】**：展示对接失败、重试次数和失败原因；超过限制次数后告警，不无限重试。**验收检查**：注入对接失败可收到最终告警。**依据**：S-9。
- [ ] **S2-37｜充电期间运动限制【硬性/P0】**：充电状态下普通任务启动和常规移动指令应被禁止或拒绝。**验收检查**：从界面尝试错误下发时有清楚提示，机器人不运动。**依据**：S-9。
- [ ] **S2-38｜自主/手动充电兼容状态【硬性/P1】**：区分自动对接与人工充电等充电来源及当前状态。**验收检查**：两类充电方式能被正确监控，真实能力以硬件实现为准。**依据**：C-附件三。
- [ ] **S2-39｜故障码、等级和文字描述【硬性/P0】**：统一展示低电、传感器、定位、电机、运动受阻、通信等异常的编码、严重性和处置建议。**验收检查**：故障记录含代码、描述、发生与恢复时间。**依据**：C-附件一18；S-8。
- [ ] **S2-40｜传感器心跳与新鲜度【硬性/P0】**：查看关键传感器最近上报、健康、无数据/异常状态。**验收检查**：故障注入后能定位具体异常设备。**依据**：C-附件一19；S-3、S-8。
- [ ] **S2-41｜定位质量状态【硬性/P0】**：至少显示正常、降级、丢失及重定位状态；丢失或跳变时机器人安全停车。**验收检查**：状态与机器人真实行为一致。**依据**：S-4。
- [ ] **S2-42｜安全停车与急停状态显示【硬性/P0】**：区分近场安全停车、软指令停止、硬件急停、故障停车；远端按钮不能替代物理急停。**验收检查**：触发各类保护后状态清楚且安全优先级正确。**依据**：C-附件一18；S-6。
- [ ] **S2-43｜故障解除与恢复条件【硬性/P0】**：安全类故障清除后须重新核查核心传感器、定位和安全区域，满足条件后才允许恢复。**验收检查**：危险条件未消除前，远端恢复指令被拒绝。**依据**：S-8。
- [ ] **S2-44｜故障事件前后日志关联【硬性/P0】**：故障详情直接关联对应时段关键状态、控制日志和地图/软件版本。**验收检查**：能还原一次障碍导致的停车或传感器故障过程。**依据**：S-2、S-8。

**S2 退出条件**：合同列明的必备业务功能能够实机演示；引导讲解的移动、动作、语音均支持有效暂停/恢复；本体屏独立可用；故障、回充和业务识别具备真实事件证据；第二/第三优先级功能的当期验收范围已书面明确。

## 五、S3：安全、可靠性、版本管理、测试与正式交付

### 5.1 网络安全与操作审计

- [ ] **S3-01｜登录与会话控制【硬性/P0】**：远端操作必须通过身份认证，具备登录状态超时与注销能力。**验收检查**：未认证用户不能调用控制接口。**依据**：S-10。
- [ ] **S3-02｜操作权限划分【实现/P1】**：至少分离查看与控制/配置权限，减少误操作；可按管理员、操作员、只读用户实施。**验收检查**：只读账号无法下发移动或修改地图。**依据**：S-10（认证与控制安全）。
- [ ] **S3-03｜重要操作二次确认【硬性能力+实现/P0】**：对发布地图、强制任务、取消任务、回充策略修改等提供确认回执；机器人端再次校验合法性。**验收检查**：用户能看到机器人确认/拒绝的真实结果。**依据**：S-10。
- [ ] **S3-04｜关键参数校验【硬性/P0】**：校验限速值、低电阈值、目标坐标、区域范围等参数，防止无效/危险配置进入机器人。**验收检查**：越界参数提交失败并给出原因。**依据**：S-10。
- [ ] **S3-05｜传输加密与凭据保护【硬性/P0】**：平台与机器人按部署网络采用加密链路，密钥/Token 不写死在前端源码或公开日志。**验收检查**：接口测试验证非法/明文未授权访问被拦截。**依据**：R-7；S-10。
- [ ] **S3-06｜操作审计日志【实现/P1】**：记录用户对任务、地图、告警处置、阈值及版本的操作。**验收检查**：能追踪何人在何时做了何项变更。**依据**：S-2、S-10（追溯）。
- [ ] **S3-07｜数据最小化与权限保护【硬性/P0】**：对现场图像、人员信息、人脸数据、业务数据等按合同授权范围处理，不向无关第三方披露。**验收检查**：数据查看/导出受控，数据处理流程与甲方要求一致。**依据**：C-附件一18；R-4；S-11。

### 5.2 数据、地图、模型、参数和任务版本管理

- [ ] **S3-08｜软件版本信息【硬性/P0】**：记录远端前端、后台、ROS2 节点、本体界面的版本和构建信息。**验收检查**：能知道每次测试对应的代码版本。**依据**：R-1；S-11～12。
- [ ] **S3-09｜地图版本关联【硬性/P0】**：每份导航地图具有唯一版本及生效记录，并关联巡检点、区域、任务。**验收检查**：查询历史任务可确定当时使用的地图。**依据**：R-2；S-4、S-11。
- [ ] **S3-10｜模型、阈值与部署版本【硬性/P0】**：登记业务识别模型、阈值、部署配置的版本，支持追溯测试对应版本。**验收检查**：可从识别事件追踪模型/阈值配置。**依据**：S-11。
- [ ] **S3-11｜任务配置版本【硬性/P0】**：保留巡检任务模板及执行时快照，避免修改模板后篡改既有记录。**验收检查**：历史任务配置可以独立查看。**依据**：R-1；S-11。
- [ ] **S3-12｜稳定版本保留和升级回归【硬性/P0】**：软件或模型升级前运行必要回归测试，保留稳定版本及版本变更记录。**验收检查**：可核对每次升级的测试结论和可恢复版本。**依据**：S-11。
- [ ] **S3-13｜配置备份和恢复【实现/P1】**：备份地图、区域、点位、任务模板和系统参数，可在受控条件下恢复。**验收检查**：模拟误删或环境迁移后能恢复可用配置。**依据**：工程建议，服务于 S-11 可追溯性。

### 5.3 日志、证据、问题定位与运维

- [ ] **S3-14｜任务运行日志【硬性/P0】**：按任务 ID 记录到点、动作、重规划、暂停/恢复、失败与完成事件。**验收检查**：可查询一次完整巡检的时间线。**依据**：S-2、S-9。
- [ ] **S3-15｜定位/规划与避障日志【硬性/P0】**：保留定位状态、全局规划失败原因、障碍/安全停车等关键日志；不要求平台渲染全部原始点云。**验收检查**：可定位一次路径失败的原因。**依据**：S-2、S-4～6。
- [ ] **S3-16｜业务事件与证据归档【硬性/P0】**：按事件统一保存关键图像、状态、置信度/判定信息、时间与位置（具体字段依识别类型）。**验收检查**：历史事件证据可查看且关联关系正确。**依据**：S-7。
- [ ] **S3-17｜故障前后关键日志【硬性/P0】**：本地保留故障发生前后必要状态，按配置上传平台。**验收检查**：故障注入后能取回诊断日志。**依据**：S-2、S-8。
- [ ] **S3-18｜日志搜索与导出【硬性/P0】**：按设备、时间、任务、错误码检索重要日志，并导出可用于研发和验收的记录。**验收检查**：导出文件包含时间、关联 ID 和实际内容。**依据**：C-附件一19；S-2、S-10。
- [ ] **S3-19｜断网补传审计【硬性/P0】**：记录离线起止时间、缓存数量、补传是否成功及失败原因。**验收检查**：断网测试后能识别哪些数据被补传。**依据**：S-2、S-10。
- [ ] **S3-20｜异常信息与用户提示【实现/P1】**：区分“任务被拒绝”“网络无响应”“机器人执行失败”“传感器不可用”等不同错误，而非仅显示操作失败。**验收检查**：任一关键失败都有可理解的提示与日志。**依据**：S-8、S-12。
- [ ] **S3-21｜运维诊断入口【实现/P1】**：汇总连接状态、接口延迟、消息过期、存储空间和关键进程状态。**验收检查**：能帮助现场定位“为什么没收到数据/为什么任务没启动”。**依据**：S-2、S-8、S-12。

### 5.4 必做的真实联动测试与验收场景

- [ ] **S3-22｜建图和地图切换测试【硬性/P0】**：在园区/楼宇目标区域建图，检查地图质量，保存/加载后完成重定位。**验收证据**：地图文件、版本、录像、测试记录。**依据**：C-附件一21；S-4。
- [ ] **S3-23｜巡检任务完整链路测试【硬性/P0】**：设置点位、下发任务、机器人导航到点、执行拍摄/识别/播报、上报结果。**验收证据**：任务 ID、界面录屏、机器人日志、结果数据。**依据**：C-附件一19、21；S-9。
- [ ] **S3-24｜暂停/恢复/取消/失败重试测试【硬性/P0】**：分别在移动、动作、播报环节验证控制与回执；增加异常状态下被拒绝的案例。**验收证据**：指令记录、状态时间线、真机录像。**依据**：C-附件一21；S-9。
- [ ] **S3-25｜异常识别专项测试【硬性/P0】**：分类型验证火/烟、积水/漏滴水、堵塞、安全帽、消防设施、入侵等适用事件；分级识别能力按书面确认范围测试。**验收证据**：测试场景、原始证据、事件结果与指标统计。**依据**：C-附件一18、附件三；S-7。
- [ ] **S3-26｜动态和低位障碍安全测试【硬性/P0】**：覆盖静态/动态、叉臂/托盘低位、狭窄通道、盲角、倒车/旋转、斜坡等适用工况。**验收证据**：停车/减速/绕障数据与视频。**依据**：S-6。
- [ ] **S3-27｜定位降级/丢失测试【硬性/P0】**：在典型弱特征场景或受控故障下验证定位正常/降级/丢失，以及丢失停车与重定位恢复。**验收证据**：状态变化日志与机器人行为。**依据**：S-4。
- [ ] **S3-28｜断网/重连与离线安全测试【硬性/P0】**：运行期间断开 5G/Wi-Fi，验证端侧按策略继续或安全停止，重连后补传。**验收证据**：完整事件序列和补传记录。**依据**：R-1、R-7；S-2、S-10。
- [ ] **S3-29｜低电回充与充电保护测试【硬性/P0】**：验证阈值、自动回充、对接失败有限重试、充电状态及普通移动禁止。**验收证据**：BMS 曲线/状态、回充日志、失败原因。**依据**：C-附件三；S-9。
- [ ] **S3-30｜界面故障隔离测试【硬性/P0】**：人为关闭本体触摸屏或远端前端，在受控条件下检查核心避障/控制不受影响。**验收证据**：异常前后日志和安全状态。**依据**：S-10、S-12。
- [ ] **S3-31｜通信鉴权/配置校验测试【硬性/P0】**：尝试匿名下发、越权下发、非法地图区域或越界阈值。**验收证据**：拦截日志和错误回执。**依据**：S-10。
- [ ] **S3-32｜日志与版本追溯测试【硬性/P0】**：从一条异常倒查任务、机器人、地图、模型与软件版本、故障日志并导出。**验收证据**：导出日志和关联截图。**依据**：S-2、S-11。
- [ ] **S3-33｜量化性能指标实测【硬性/P0】**：按附件三实测导航、定位、续航/充电和识别相关指标；平台可展示数据，但必须使用实测记录证明。**验收证据**：测试报告、原始数据、测试条件及版本。**依据**：C-附件三；S-附表A18。

## 六、S4：建议后置的增强功能（不计入基础平台验收，除非另有约定）

- [ ] **S4-01｜实时视频监看【增强/P2】**：在管理端播放可见光/热红外实时流。摄像头本身的实时视频能力在附件一硬件需求中提及，但“远端平台必须提供完整直播页面”未被单独明确，建议需求评审确认。
- [ ] **S4-02｜三维点云高性能可视化【增强/P2】**：在浏览器/Qt 中实时查看点云与三维定位结果，方便研发调试；不代替机器人端实际三维建图能力。
- [ ] **S4-03｜局部代价地图及控制曲线【增强/P2】**：展示障碍膨胀、规划路径、线/角速度及控制输出，供算法调试使用；不作为基础运维界面的强制功能。
- [ ] **S4-04｜遥控驾驶/虚拟摇杆【增强/P2】**：提供受权限、限速、失联保护约束的远程手动控制；附件一第21项没有明确要求必须配置网页摇杆，严禁以此替代本地安全保护。
- [ ] **S4-05｜高级任务编辑器【增强/P2】**：支持拖拽式任务流程、条件分支、复杂动作链与任务模拟，提升多场景维护效率。
- [ ] **S4-06｜多机器人集群调度【增强/P2】**：统一任务排队、跨设备分配与冲突调度；当前合同以首台样机和机器人级 BMS 控制为主，不应默认扩大为集群项目。
- [ ] **S4-07｜统计分析及报表中心【增强/P2】**：按日/周/月分析巡检覆盖率、任务完成率、告警分布、设备可用性，支持图表和报表输出。
- [ ] **S4-08｜第三方通知渠道【增强/P2】**：接入企业微信、短信、邮件或其他业务系统，实现告警主动触达；应额外评审信息安全与第三方接口。
- [ ] **S4-09｜云端模型训练/标注后台【增强/P2】**：辅助数据集标注、训练发布和效果分析；合同要求模型与数据的研发验证及版本化，但不等于必须建设在线训练平台。
- [ ] **S4-10｜跨园区集中管理及移动端【增强/P2】**：支持多站点、移动端适配和远程集中监管；在初版稳定运行后实施。

## 七、数据字段与通信接口最低对接清单

> 下表是为上述功能提出的**推荐接口/字段设计**，不表示合同指定必须采用这些命名或 REST 路径。可使用 Web 后端 API、WebSocket、Qt/ROS2 网关等；核心是语义一致、支持回执、可追溯。

| 对象 / 接口能力 | 推荐必含字段或行为 | 支撑功能 |
|---|---|---|
| 机器人状态 `RobotStatus` | `robot_id`、`timestamp`、`online`、`mode`、`task_id`、`safety_state`、`battery_soc`、`data_age` | 总览、设备状态、任务、安全 |
| 位姿 `Pose/TF` | `map_id`、`frame_id`、`x`、`y`、`yaw`、`timestamp`、定位质量 | 地图定位、轨迹、点位 |
| 地图元信息 `MapMeta` | `map_id`、`version`、`building/floor`、二维/三维文件引用、状态、发布时间 | 建图、加载、版本 |
| 区域 `MapZone` | `zone_id`、地图版本、多边形、类型（禁行/限速/充电等）、规则、生效状态 | 区域与安全配置 |
| 巡检点 `InspectionPoint` | `point_id`、地图版本、位姿、名称、动作序列、关联资产 | 点位、任务执行 |
| 任务模板 `TaskTemplate` | `template_id`、类型、点位序列、动作序列、计划/周期、版本 | 常规与指定任务 |
| 任务实例 `TaskInstance` | `task_id`、`robot_id`、类型、优先级、执行状态、当前点、起止时间、失败原因 | 任务全生命周期 |
| 控制指令 `Command` | `command_id`、操作者、机器人 ID、目标任务、动作、参数、创建时间、有效期 | 下发/暂停/恢复/取消/回充 |
| 指令回执 `CommandAck` | `command_id`、是否接受、执行状态、原因码、时间 | 指令确认与追溯 |
| 巡检结果 `InspectionResult` | `result_id`、`task_id`、`point_id`、类型、结果、证据、采集时间 | 到点动作、事件上报 |
| 风险事件 `RiskEvent` | `event_id`、类别、等级、机器人/任务/资产 ID、位置、时间、确认状态、证据引用、处理状态 | 识别告警中心 |
| BMS 状态 `BmsStatus` | `robot_id`、`soc`、充电状态、保护/故障码、时间；电压/电流/温度按硬件可用字段 | BMS、回充 |
| 故障 `FaultEvent` | `fault_id`、设备/模块、故障码、等级、发生/恢复时间、处理动作、日志引用 | 设备健康与故障诊断 |
| 讲解 `GuideContent` | `content_id`、文字/语音资源、关联点位、版本、启用状态 | 引导讲解 |
| 版本记录 `VersionRecord` | 软件、地图、模型、参数、任务版本、发布人、时间和验证记录 | 追溯与回归 |
| 日志检索 `LogQuery` | 按设备/任务/日期/故障码过滤、结果分页、导出及权限控制 | 诊断、交付、验收 |
| 离线补传 `SyncRecord` | 断线区间、缓存事件 ID、补传状态、重试与去重结果 | 弱网恢复 |

### 建议明确的控制命令

`StartMapping`、`SaveMap`、`LoadMap`、`PublishZone`、`StartTask`、`PauseTask`、`ResumeTask`、`CancelTask`、`RetryTask`、`StartGuide`、`RequestDocking`、`GetRobotStatus`、`GetFaults`、`QueryLogs`。

- [ ] **IF-01｜消息规范确认【实现/P0】**：研发、前端、ROS2、测试共同审阅字段定义、单位、坐标系、状态枚举与时间格式；双方对变更有版本记录。
- [ ] **IF-02｜接口错误处理【硬性能力+实现/P0】**：定义超时、未认证、无权限、参数非法、定位丢失、忙碌、急停、充电中、路径失败等通用错误及用户可读提示。

## 八、验收指标与测试证据对应表

> 以下指标来自合同附件三及附件一。**平台的责任是展示、记录或导出必要数据；是否达标需依赖独立实测和整机结果**。部分指标属于硬件、算法或整机能力，不应错误归类为“做一个网页即可通过”。

| 合同指标/要求 | 约定内容 | 平台应配合提供的能力 | 主要验收证据 |
|---|---|---|---|
| 默认移动速度 | 0.5 m/s | 展示/配置状态时正确使用单位和生效值 | 整机实测记录 |
| 最大移动速度 | 1.2 m/s | 限速区参数不得超过机器人安全允许值 | 测试记录、底盘日志 |
| 静态定位精度 | ≤±10 cm | 地图定位和版本记录 | 定位测试报告 |
| 动态定位精度 | ≤±12 cm | 轨迹和定位状态记录 | 动态定位测试 |
| 重复定位精度 | ≤±10 cm | 记录任务点位与地图版本 | 多次重复定位测试 |
| 定位响应时间 | ≤0.3 s | 时间戳、定位状态追溯 | 定位响应测试 |
| 爬坡能力 | ≥7° | 可归档测试工况与状态日志 | 整机斜坡试验 |
| 额定负载 | ≥20 kg | 可记录相应测试结果 | 硬件/整机测试 |
| 连续作业续航 | ≥2 小时（满电、常规巡检速度） | SOC、任务时间线、充放电记录 | 续航测试 |
| 充满电时间 | ≤2 小时 | 充电开始/结束状态与 BMS 数据 | 充电测试 |
| 低电阈值 | 可自定义，默认20% | 阈值配置及告警/回充动作记录 | 功能测试 |
| 充电方式 | 自主充电 + 手动充电兼容 | 展示回充、充电、失败状态 | 回充/手充测试 |
| 火焰检测距离 | 0.5～5 m（附件一） | 记录火情告警、场景及证据 | 对应距离的整机识别测试 |
| 异常识别准确率 | ≥90%（附件一火情模块文字） | 存档样本、识别结果和分类统计 | 按正式验收定义计算的测试报告 |
| 仓库/机场/园区风险 | 适用场景下的火烟、积漏滴水、堵塞、消防设施等；仓库含安全帽/入侵 | 对应事件类型、位置、证据和查询 | 分场景事件测试 |
| 防水等级 | IP65 | 可留存测试报告或设备参数，不是界面功能 | 防护等级证明/测试 |
| 避雨识别 | 自动 | 雨情、避雨任务和状态记录 | 户外场景测试 |
| 试运行期 | 不少于30天且无重大缺陷 | 全程任务、状态、告警与故障数据留存 | 试运行报告和原始记录 |

**提示**：识别指标的测试样本、统计方式、场景边界、低优先级能力验收安排，应在测试计划中与甲方共同确认，不应自行新增未约定的通过阈值。

## 十一、最终建议与注意事项

1. **先把 S0 + S1 做成真实联动闭环**，不要只做静态展示大屏；地图、任务、状态、结果、故障必须连通同一台机器人。
2. **S2 和 S3 是最终交付需要补齐的内容**，不是“有空再做”的可选项。只有 S4 才是真正可后置的增强功能。
3. **机器人端安全控制不属于网页逻辑**：急停、近场检测、底盘控制、低电回充和定位失效保护都必须以本地实现为准。
4. **远端 Web 优先，Qt 按设备调试需要选用**；二者是技术选型，不是合同强制选型。本体安卓/鸿蒙等触摸屏应单独完成。
5. **量化指标靠整机测试，不靠 UI 数字**。建议开发初期同步建立验收数据留存机制，避免试运行时找不到证据。
6. **保留第二/第三优先级功能**：人脸、货位识别要写进总体需求，具体排期与是否参与首批验收应由双方书面确认。

**一句话目标**：交付一套能真实完成“建图—配置—巡检—识别—告警—控制—诊断—追溯”的综合平台，同时满足机器人本体触摸屏、离线安全和合同验收交付要求。
