# 上位机接口说明：cmd__ 控制（26 字节）+ sta__ 反馈（56 字节）

本文档是上位机与底盘之间 UDP 链路的唯一接口说明，两个方向都覆盖：

- **上位机 → 板端**：`cmd__` 26 字节控制帧，见第 3 节。
- **板端 → 上位机**：`sta__` 56 字节状态帧，见第 5 节。

## 适用范围

本包供上位机工程师实现 UDP 收发、协议校验、状态有效位处理和台架联调。
下述网络及反馈行为需在对应修改版固件编译、烧录后验证，不能据此认为现场旧板已经升级。
`sta__` 为 **56 字节**版，Version=1；**旧 48 字节版同样使用 Version=1，长度是两版唯一的区分标志**。
当前实际速度、实际转角、编码器、真实设备使能和硬件故障均无有效数据来源，不能用于 wheel odom 或实际状态闭环。有效位为 0 时的数值 0 不代表车静止、转向回中或设备无故障。

本文档整合并取代原 `docs/上位机对接说明.txt`（2026-09-17，48 字节暂定版，**已删除**）。整合时保留了三处**跨修订版的差异记录**，因为它们各自对应过真实的实现错误，删掉就没人知道旧版长什么样了：`Counter` 的宽度（5.1）、`RequestedEnable` 的消失（5.1）、转角比例 1deg/count→0.1deg/count（5.1）。

## 1. 口径与配置

本版本以用户《普通车运控_底盘状态反馈与轮式里程计数据需求说明_V1.0.docx》第 6 节的 56 字节示例为最终接口：偏移、类型、计数器、有效位、比例和校验位置均按该表实现。保留原 UDP cmd__26 控制、CAN 控制发送、USART1 和 USART3 遥控。替换以前 48/128 字节版状态包及解析脚本。

用户已指示"先按照旧代码的标准来"。本包采用当前实际编译的 User 版本：线速度=实测 RT49 RPM/3000，转角=EPS 实际角度 deg，比例 1、零偏 0。收到新鲜反馈即回传对应值并置有效位；不是把目标指令当作反馈。该临时口径在 FaultFlags 位 19/20 明示，未声称已经完成轮速/等效前轮角的实车标定。需求第 8 节关于等效前轮物理角度的最终标定仍应在后续验收确认。

**转角比例此后经实车修正**：原始计数 300 对应现实 30°，即 0.1deg/count（见 5.1、5.6）。速度系数口径未变。上位机换算规则不受影响（仍只 ÷10000）。

## 2. 网络配置

| 项 | 值 |
|---|---|
| STM32 | 192.168.5.50，掩码 255.255.255.0 |
| 工控机专用网口 | 192.168.5.11，掩码 255.255.255.0 |
| 上位机下发 | 任意本地 UDP 源端口 → 192.168.5.50:5000 |
| STM32 反馈 | 192.168.5.50:5001 → 192.168.5.11:5001 |

- 上位机应监听 192.168.5.11:5001，放行 UDP 5001 入站。
- 目标反馈周期 20ms，约 50Hz；状态 UDP 源/目标端口均为 5001，**不要求 ACK**。
- STM32 主动 ARP 解析工控机 MAC，**反馈不要求先收到 cmd__**，因此接收端可以独立于发送端启动。
- ARP 或 DMA 忙可能丢包，`Counter` 按发送尝试递增（不是按成功发送递增）。
- **轻量网络栈没有 ICMP，不以 ping 是否成功作为 UDP 通信验收依据。**
- 无跨网段路由；雷达的 192.168.1.0/24 继续使用另一个网口。
- 收到 UDP 报文不等于执行器已执行；上位机必须**独立**判断 UDP 通信超时（见 5.2）。

## 3. cmd__ 控制协议（26 字节）

偏移从 0 开始，多字节 Big-Endian，有符号值为补码。

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 5 | ASCII `cmd__` |
| 5 | 1 | Version，现有发送使用 1 |
| 6 | 1 | Mode：0 disable、1 auto、2 debug |
| 7 | 1 | Flags：bit0 EStop、bit1 EPS 回中、bit2 SEB 自动制动、bit3 SEB 对齐 |
| 8 | 1 | EnableMask：bit0 RT49、bit1 EPS、bit2 SEB |
| 9 | 4 | int32 速度请求，m/s ×10000 |
| 13 | 4 | int32 EPS 请求，固件解析为 raw/10000；**EPS 控制物理单位及车轮转角标定须与下位机工程师确认，不要由此推导实际车轮转角** |
| 17 | 1 | SEB 模式：0 none、1 pressure、2 stroke、3 alignment、4 autobrake |
| 18 | 2 | int16 SEB 请求：压力 MPa×100，行程 mm×10，按模式解释 |
| 20 | 1 | Light，保留原字段；本说明不承诺灯控已实现 |
| 21 | 1 | Counter，uint8，由上位机维护 |
| 22 | 4 | Checksum，uint32：按字节累加 frame[0..21]，结果 Big-Endian |

发送约定：

- 建议每个 UDP 报文只携带一帧完整 cmd__，长度正好 26 字节。
- 正常持续下发建议 20ms。原控制超时条件为无有效指令，或距离最近有效指令 >500ms。
- 当前实现由 UDP 接收层先检查累加和，再解析指令；**Version 字段本身没有额外拒绝逻辑，不要误认为固件已经拒收所有非 1 版本。**
- UDP 和 USART1 均可更新同一个命令快照；主循环 USART1 解析后再处理 UDP。

## 4. 命令快照与遥控接管

- 当 CH5 健康使能时，遥控在控制任务前覆盖命令快照。
- 健康 CH5 关闭会**释放**接管；上位机需持续发送新鲜指令替换旧快照。
- 已经接管后的遥控超时/丢帧/failsafe，继续输出原版安全指令，直到收到健康 CH5 关闭帧。**并非曾收到遥控帧就永久接管。**

## 5. sta__ 状态协议（56 字节）

只接受长度 56、头 `sta__`、Version=1 且累加和正确的报文；未知长度或版本应**拒绝并记录**，不得静默接受。Checksum = `sum(byte0..51) & 0xFFFFFFFF`，**不是 CRC，也不是按 32 位字分组求和**。全部多字节字段 Big-Endian，带符号为补码。

### 5.1 最终字节布局

| 偏移 | 类型 | 字段/定义 |
|---|---|---|
| 0..4 | ASCII | `sta__` |
| 5 | u8 | Version=1 |
| 6 | u8 | ValidFlags，见 5.2 |
| 7 | u8 | ControlSource：0 安全/无新鲜命令，1 UDP，2 遥控，3 USART1，4 内部/本地调试 |
| 8 | u8 | EnableState：位 0 RT49、1 EPS、2 SEB；实际 SEB 使能从 CAN 读取。未知使能位写 0，但必须结合 FaultFlags 位 13..15 区分未知/失能 |
| 9 | u8 | Counter，0..255 回绕 |
| 10..13 | u32 | TimestampMs，STM32 本控制周期汇总反馈的启动时间 ms，不是 UDP 到达时间 |
| 14..21 | i64 | DriveEncoderCount，pulse；三协议未提供累计计数，当前 0 且 ValidFlags 位 0 清除 |
| 22..25 | i32 | ActualSpeed，m/s×10000，当前按旧版实测 RPM/3000 换算；CAN 无效时 0 且位 1 清除 |
| 26..29 | i32 | ActualSteeringAngle，当前旧版口径按 EPS 实际角度 deg×10000 直接回传，位 2 随反馈有效；是否等同物理前轮角尚未标定，位 20 明示临时口径 |
| 30..33 | i32 | SteeringRaw，EPS 0x18F signed16 实际角度**原始 count** 符号扩展为 i32（保留原始计数，不换算）。如需角度：原始值 ÷10 → °，实车确认原始 300 对应 30°。例如 `FF9C`→−100count→−10.0° 设备实际角度，**该字段正常随真实 CAN 反馈变化** |
| 34 | u8 | BrakeMode，从 SEB 实际反馈模式取得：0 未知/故障，1 压力，2 行程 |
| 35..36 | i16 | BrakeActual，压力 MPa×100，行程 mm×10；以 BrakeMode 解释。无效写 0 并清位 4 |
| 37 | i8 | Gear：由实测 RPM 符号归一化 +1 前进、−1 倒退、0 静止/未知；不是独立挡位传感器，停车时不能据此推断实际挡位 |
| 38..39 | u16 | RT49Status，归一化驱动反馈状态，见 5.3 |
| 40..41 | u16 | EPSStatus，归一化 EPS 模式/可控状态，见 5.3 |
| 42..43 | u16 | SEBStatus，低 8 位保留原 0x722 byte0，高 8 位 0 |
| 44..47 | u32 | FaultFlags，系统状态/故障汇总，见 5.4；它始终可解释，不能用"设备有效位=0"忽略通信故障 |
| 48 | u8 | LastCmdCounter，最近合法且被软件接受的 UDP/USART1 cmd__ 计数，非 CAN 执行成功确认。未收到命令时 0 且 FaultFlags 位 18=1 |
| 49..51 | bytes | Reserved = 00 00 00 |
| 52..55 | u32 | Checksum |

**三处跨修订版差异（阅读旧资料时必看）**

- **Counter 的宽度**：48 字节版说明称 `Counter` 为 uint32，56 字节版明确为 **u8（0..255 回绕）**。以本文档为准。差分回绕计算必须按字段实际宽度掩码，用 32 位去掩一个 u8 回绕会得到约 4.29e9 而不是 1 —— 一个看起来合理、不会报错的错数。约 49.7 天的 `TimestampMs` 回绕、`Counter` 回绕、STM32 重启要**分别**处理，不能混为一谈。差分可用 `(delta & mask)`，不能用普通有符号大小比较判断新旧。
- **`RequestedEnable` 已不存在**：48 字节版中的 `RequestedEnable` 字段在 56 字节版里**没有**。真实硬件使能状态改由 `EnableState`（位 0..2）+ FaultFlags 位 13..15 表达。不得用软件请求宣称驱动或转向真的已使能。
- **转角比例从 1deg/count 改为 0.1deg/count**：早期按 EPS Excel 矩阵与"先按旧代码标准来"采用的 1deg/count 口径，被实车确认推翻（原始 300 ↔ 30°）。同一物理角度的两个字段值随之差 10 倍：旧口径 `FF9C`→ActualSteeringAngle −1000000，新口径→**−1000**。上位机的换算规则不变（仍只 ÷10000），因为 ÷10 由 STM32 完成；**但任何按旧口径看过数据的人都要按 10 倍重新理解，且上位机绝不能再补一次 ÷10。**

### 5.2 ValidFlags 与无效值

| 位 | 说明 |
|---|---|
| 0 | 真实累计编码器有效，当前未有协议来源，**不得积分 RPM 冒充编码器** |
| 1 | 实测 RPM 按所选口径换算的线速度有效：默认旧版 3000RPM/(m/s)，RT49 新鲜 |
| 2 | 实测角度按所选口径回传有效：默认直接 EPS 实际角度，EPS 新鲜；必须结合 FaultFlags 位 20 识别是否已确认等效前轮映射 |
| 3 | SteeringRaw 有效：收到新鲜的 EPS 实际角度报文，无需车轮机械映射即可回传 |
| 4 | BrakeActual 有效：SEB 新鲜、模式已知、该模式实际值范围有效，且未提示无压力传感器 |
| 5 | RT49 状态新鲜 |
| 6 | EPS 状态新鲜 |
| 7 | SEB 状态新鲜 |

- 状态新鲜期限 **200ms**；EPS 故障两页和 SEB 错误报文各自 **500ms**。
- 转角两项正常时 `ValidFlags & 0x0C` 应为 `0x0C`（bit2 换算角度 + bit3 原始角度）。这个掩码是现场判断"EPS 那一路通没通"最快的单一信号。
- **字节值 0 并不自动代表无效，以 ValidFlags 为准**；有效是"已接收且未超时"，不能替代故障检查。
- 保留位忽略，**不得把整个报文到达视为所有数据都有效**。
- 采样来自各设备异步 CAN，`TimestampMs` 是周期汇总时间，不声称所有传感器同时硬件采样；各收到时间和有效分组可在 `g_vehicle_status` 与 Watch 查看。`TimestampMs` 既不是 CAN 采样时间，也不是工控机墙钟；未来接入真实轮式里程计前还需要采样时间定义及标定。
- **当前可靠信息**：帧计数、开机组包时间、当前命令快照来源，以及收到过有效上位机指令后的 `LastCmdCounter`。
- `LastCmdCounter` 代表最后通过校验并被解析接收的 UDP 或 USART1 指令，**不是设备执行确认**；即使遥控覆盖，该值仍可更新。
- `Counter` 缺口（ARP 等待、DMA 忙、网络丢包）**不应自动归因于车辆故障**。
- 上位机请按**本机单调时钟**记录接收时间，并设置可配置的反馈失联判断。建议联调初值 **200ms**；这是上位机观测阈值，不是已实现的新板端停车条件。

### 5.3 状态/故障枚举

**RT49Status**：位 0..7 原故障码；位 8 有新鲜 RT49 反馈；位 9 实测 RPM 正向，位 10 负向，位 11 零 RPM。故障码非 0 表示自身故障；文档没有定义各码名称，**不能杜撰**。实际 RPM、电流、温度保留在 `g_vehicle_status`，56 字节示例没有额外诊断字段，未侵占 Reserved。

**EPSStatus**：位 0 当前模式（0 手动、1 自动）；位 1..2 实际控制状态（1 可控、2 暂不可控、3 严重故障，0 未定义），例如 mode1/state1→`0x0003`。模式与"可控"不能直接视作真正硬件使能。

**SEBStatus**：位 0 对中完成、1 实际控制使能、2..3 实际模式（0 行程、1 压力、2 故障、3 保留）、4 自动刹车、6..7 故障级别（0 无、1 轻微、2 普通、3 严重），其余原始位保留。

### 5.4 FaultFlags

位 0..10 按需求文档第 6.2 节实现，其余为此次明确冻结的诊断扩展；FaultFlags 既有故障也有接管/未配置状态，**不可把所有非 0 简单当作严重故障**。

| 位 | 定义 |
|---|---|
| 0 | 无新鲜 RT49 状态/通信超时 |
| 1 | 无新鲜 EPS 状态/通信超时 |
| 2 | 无新鲜 SEB 状态/通信超时 |
| 3 | 新鲜 RT49 故障码非 0 |
| 4 | 新鲜 EPS 暂不可控/严重故障，或任何新鲜故障页非 0/故障等级非 0 |
| 5 | 新鲜 SEB 状态故障级别非 0/故障模式，或新鲜 SEB 错误码非 0 |
| 6 | 最近软件控制命令带急停请求，不声称有独立急停开关采样 |
| 7 | 当前控制命令无效/超过 500ms 未更新；遥控安全停车指令是有效指令时，此位不会代替位 12 |
| 8 | 遥控正在接管，包括接管后失联安全锁存 |
| 9 | 真实编码器数据无效/未提供 |
| 10 | 等效前轮转角无效/未标定；**此位不表示 SteeringRaw 一定无效，请同时查看 ValidFlags 位 3** |
| 11 | 线速度数据无效/换算参数尚未确认 |
| 12 | 遥控接管后失联/故障，原版锁存安全停车指令 |
| 13 | RT49 实际使能未知；协议未提供使能反馈，默认 1 |
| 14 | EPS 实际使能未知；模式/可控不冒充使能，默认 1 |
| 15 | SEB 实际使能未知；状态超时为 1，新鲜状态可确定使能/失能时为 0 |
| 16 | EPS 故障表两页未全部新鲜，不能认定完整故障表无故障；单页非 0 仍置位 4 |
| 17 | 当前模式 BrakeActual 无效/模式未知/超范围/无压力传感器 |
| 18 | 尚未接受任何 UDP/USART1 命令，LastCmdCounter 未知 |
| 19 | 已选择旧版速度系数，实车速度标定未确认；**是口径说明，不是 CAN 失效** |
| 20 | 已选择直接 EPS 角度口径，等效前轮角机械映射未确认；**是口径说明，不是 EPS 数据失效** |
| 21..31 | 保留 0 |

位 11、19、20 在健康板子上也会置位（它们描述的是"未标定/未确认"，不是故障）。上位机做故障汇总展示时应把这类口径位与真实故障分开，否则真实故障会被淹没。

### 5.5 CAN 字段来源

**RT49** Word"上报指令"、示例 2：CAN2 500kbps，标准数据帧 8 字节，现控制 ID `0x301` 对应反馈 `0x401`。11 字节示例中前 3 字节为传输封装，真正 CAN payload 从 `01` 类型开始。data1/2 signedBE 实测 RPM，data3 电流 A，data4 温度 ℃，data5 故障码；**没有直接 m/s 字段或累计编码器字段**。`01 01 F5 46 3C 00 00 00` = 501RPM/70A/60℃/故障 0，值来自实际反馈，非控制目标。

**EPS** Excel motorla314 A17/A20..A23 及用户截图：CAN1 250kbps，`0x18F`，20ms。Motorola 采用 LSB 起始位写法：角度高 data1/低 data2 signed16；**Excel 矩阵标称 1deg/count，但实车确认该字段原始 300 对应现实 30°，即实际 0.1deg/count（见 5.6），以实车为准**；电流高 data3/低 data4，0.1A/count；温度 data6，当前控制状态 data7 低 2 位，模式 data0 bit0。EPS 温度 signed8 与文档最大 150 矛盾，保留原始字节在 Watch，本包不擅自给出修正后的温度。已按用户截图选用 motorla314，不再将此角度留在旧 128 字节扩展区。

**EPS 故障** `0x700`：data6=00，data0..5 为 Failtable0..5；data6=FF，data0..5 为 Failtable6..11，data7 故障等级。两页独立过期，部分页有故障也汇总到 FaultFlags。**若实车是 Intel/324 版本，不能只修改字节序就认定其"目标角度"字段为实际测量，应先确认实际矩阵。**

**SEB** PDF 物理第 2 页、印刷 4/10：CAN2 500kbps，`0x722` 10ms 状态、`0x731` 100ms 错误。状态 data0 提供实际模式/使能/故障。行程高 data1/低 data2，mm = raw×0.05−30；压力 data3×0.05MPa；设备角度高 data4/低 data5 signed×0.5deg 保留在 Watch，**不当作车轮角**。启用生命计数/校验时检查 data6、data7；重复生命计数不刷新测量时间，错误校验报文丢弃。

**BrakeActual 换算** = 压力 `pressure_kPa/10`，行程 `stroke_µm/100`（signed，截断趋零；0.05mm 的 CAN 精度转换为文档 0.1mm 精度）。SEB 故障/保留模式 BrakeMode=0，清有效位 4；**不能使用下发的 SEB Mode 决定实际反馈单位**。行程范围 −5..27mm，压力 0..5MPa；超范围清该值有效位。`0x731` data1 bit3（无压力传感器）新鲜时压力清有效位，即便报文原数为 0 也不冒充实测。

### 5.6 线速度与车轮角换算配置

代码已实现两种 RPM→线速度方法，**仅使用实测 RPM**：

- `METHOD=1`：`v = RPM / VEH_FEEDBACK_RPM_PER_MPS × SIGN`
- `METHOD=2`：`v = RPM × 2π × effective_wheel_radius / (60 × motor_to_wheel_gear_ratio) × SIGN`

当前默认 `VEH_FEEDBACK_USE_LEGACY_STANDARD=1`、METHOD=1，反馈 RPM_PER_MPS 直接引用当前控制的 `VEH_RT49_RPM_PER_MPS=3000.0f`。RT49 新鲜即输出换算速度有效，**包括实测 RPM=0 时的有效 0 速度**；不受当前命令是否有效影响。例：600RPM→0.2000m/s→字节字段 2000，−600RPM→−2000，501RPM→1670。`CALIBRATED=0` 仍保留，表示没有实车标定证明，FaultFlags 位 19 说明旧版系数口径。以后正式标定可关闭 LEGACY_STANDARD、设 `CALIBRATED=1` 和已确认的 METHOD/参数。

新需求给半径 0.200m，已保留为可调整配置，当前默认比例法不使用轮径或减速比。旧未编译 `Core/upper_data.c` 中 24.068 减速比与半径 0.105m、轴距 1.205m 属于另一套备用口径，本次不将它混入当前 3000 系数标准。原控制系数与 CAN 控制输出不变。

转角换算 = `EPS实际角度deg × WHEEL_PER_EPS_DEG + WHEEL_OFFSET_DEG`。按用户此次旧标准指示，默认比例 1、偏移 0，ActualSteeringAngle 和 SteeringRaw 都从实测 `0x18F` 取得。**实车确认原始计数为 0.1deg/count（原始 300 ↔ 30°），该 ÷10 换算已在 STM32 内完成，不属于 `WHEEL_PER_EPS_DEG`**：例如 `FF9C`→SteeringRaw=−100、ActualSteeringAngle=−1000（=−10.0°）。CAN 无效时两字段归零并清各自有效位。`CALIBRATED=0` 和 FaultFlags 位 20 表示它是临时直接 EPS 角度口径，不能声称已经有等效前轮角标定；以后确认机械关系后关闭 LEGACY_STANDARD 并设 `VEH_FEEDBACK_STEER_CALIBRATED=1` 及真实映射。附接收脚本将有效回传值显示为 `steering_angle_deg`，`road_wheel_deg` 在位 20=1 时仍显示 INVALID，以免上位机误用物理含义。
